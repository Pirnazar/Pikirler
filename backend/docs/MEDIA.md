# Медиа: YouTube, кино, тексты песен и поиск

Раздел **Медиа** объединяет архив YouTube, библиотеку кино и общий поиск.
Маршруты интерфейса: `#/media`, `#/media/movies`, `#/media/search`.
Доступ требует разблокированной сессии владельца. Данные кино, индекс,
списки и сохранённые цитаты изолированы по `owner_id`.

## Архив YouTube

Pikirler читает готовый SQLite-снимок Second Brain: карточки с цветными
превью, тип `video` / `music` / `unknown`, длительность, канал, субтитры,
тексты песен и строки с таймкодами. Есть поиск, фильтр типа и пагинация.
Наличие карточки не означает, что для неё удалось получить текст.

Импорт лайков, OAuth, cookies, Whisper и получение текстов выполняет
отдельный Second Brain. Pikirler не запускает этот импорт и не меняет его
расписание. Обновление поискового индекса каждые 10 минут — отдельная задача.

В production `.env.production` задайте:

```dotenv
PIKIRLER_YOUTUBE_HOST_DIR=/mnt/media/youtube-archive
PIKIRLER_YOUTUBE_HOST_GID=1001
PIKIRLER_YOUTUBE_ARCHIVE=/srv/youtube-archive/youtube.sqlite3
PIKIRLER_YOUTUBE_ARCHIVE_OWNER_ID=<UUID владельца Pikirler>
```

Первые два параметра относятся к хосту; путь `PIKIRLER_YOUTUBE_ARCHIVE` —
к контейнеру. Каталог монтируется в API и worker только для чтения. Укажите
фактическую группу, которой разрешено читать снимок. Если UUID пустой,
архив закрыт для всех; чужой пользователь получает пустой список или 404.

Снимок должен содержать `youtube_videos`, `youtube_transcripts`,
`youtube_transcript_segments`, `song_lyrics`, `song_lyric_lines` в формате
экспортёра Second Brain. Публикуйте согласованный самостоятельный SQLite-файл
атомарной заменой в смонтированном каталоге. Чтение использует `immutable=1`:
активная база с незавершённым WAL или запись прямо в опубликованный файл
не подходят. Неизменённый файл повторно не индексируется.

Миграция `0008` сохраняет резервные PostgreSQL-таблицы будущего нативного
импортёра. Текущий экран YouTube читает SQLite, а не эти таблицы.

## Кино и реплики

**Кино → Добавить фильм**: найдите название на русском или английском,
выберите год. Повторное добавление IMDb ID не создаёт дубль у владельца.
Сохраняются постер, год, жанры, описание, режиссёр и актёры. Английские данные
из Cinemeta и русские из TMDB Addon хранятся раздельно; поиск учитывает обе
версии. Отсутствующий перевод не заменяет оригинал пустым значением.

Субтитры ищутся через OpenSubtitles REST с резервным Stremio v3.
API-ключи не нужны. Очередь независимо дополняет RU и EN, пропускает
сохранённые языки и повторяет временные ошибки до трёх попыток. В карточке
виден статус каждого языка. **Обновить данные и субтитры** повторяет поиск
недостающих данных; можно выбрать другую дорожку вручную.

Собственные SRT/VTT до 5 МБ можно загрузить в UTF-8, UTF-16 или Windows-1251.
Каждая реплика хранит язык, начало и конец. Поиск реплик работает внутри
фильма и по библиотеке с пагинацией. Ссылка на таймкод открывает выбранную
дорожку на нужной странице. Файлы фильмов не скачиваются и не проигрываются.
Доступность перевода и соответствие таймкодов монтажу зависят от источника.

В **Моя коллекция** доступны «Хочу посмотреть», «Просмотрено», избранное,
оценка 1–10 и комментарий. Личная оценка отделена от IMDb. Список просмотра
и избранное независимы. Одновременные правки защищает `preferences_version`;
при конфликте нужно перечитать карточку.

## Общий поиск

Типы: кино, видео, музыка, тексты песен; дополнительные фильтры — язык,
жанр и год выпуска/публикации. Жанры кино приходят из каталога, жанры YouTube
выводятся из категории. Поиск по словам использует PostgreSQL FTS для
русского и английского, нормализацию Unicode/туркменских букв и подстроки.

Режимы **По смыслу** и **Слова и смысл** используют отдельную локальную
модель `intfloat/multilingual-e5-small:int8:v1`: ONNX INT8, CPU, 384 измерения,
нормализованные векторы pgvector. Для запроса применяется префикс `query:`,
для фрагмента — `passage:`, предел модели — 512 токенов. Это поиск похожих
фрагментов; совпадение по смыслу приблизительное. Результаты содержат
исходный текст, источник и таймкод, без генерации новых реплик.

Production compose включает внутренний сервис `media-encoder` без
опубликованного порта. Для его использования:

```dotenv
PIKIRLER_MEDIA_ENCODER_URL=http://media-encoder:8010
PIKIRLER_MEDIA_ENCODER_MODEL=intfloat/multilingual-e5-small:int8:v1
PIKIRLER_MEDIA_MODEL_DIR=/mnt/media/models
```

Пустой URL оставляет доступным поиск по словам. Это отдельная настройка от
`PIKIRLER_EMBEDDING_*` и AI над личными заметками. При первом запуске encoder
скачивает веса и токенизатор с Hugging Face и готовит INT8. Тексты и запросы
туда не отправляются. Кэш хранится на диске; для подготовки модели в compose
выделен лимит 4 ГБ памяти. Без host-пути используется том `media_models`.
Заранее подготовьте каталог, права записи и свободное место под исходную и
квантованную модели. Проверяйте состояние сервиса и его логи при долгом старте.

Новые данные кино ставят индексацию в очередь; worker также проверяет архив
каждые 10 минут. Неизменённые фрагменты и готовые векторы сохраняются,
изменение текста или контекста названия перестраивает затронутые векторы.
Прогресс виден в общем поиске; поиск по словам работает до завершения
векторизации. Кнопка обновления ставит задание, а не блокирует HTTP-запрос.

Для первичного наполнения можно подключить свой компьютер по приватному
SSH-каналу с той же моделью, токенизатором и версиями зависимостей, что у
encoder. Скрипт не записывает медиатексты локально и пропускает уже готовые
строки с блокировками PostgreSQL:

```bash
python scripts/media_encode_local.py --ssh user@server --model-dir /path/to/model
```

В каталоге нужны копии серверной квантованной модели под именем `model.onnx`
и `tokenizer.json`; зависимости перечислены в `media_encoder/requirements.txt`.
Нужны SSH и доступ к Docker на сервере. Помощник рассчитан на стандартный
контейнер `pikirler-prod-api-1`; автоматическая работа сервера от него не зависит.

## Сохранение цитат

**В заметки** сохраняет фрагмент или отдельную строку: текст, названия на двух
языках, год, язык, таймкод и ссылку. Сервер сам разрешает ссылку на исходную
запись и проверяет владельца. Повторное сохранение открывает существующую
заметку; после её удаления можно сохранить заново. Снимок источника в
`source_metadata.media_quote` переживает обновление субтитров и индекса.

## Обновление и резервное копирование

Из каталога `backend` после настройки `.env.production` и TLS:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production build
docker compose -f docker-compose.prod.yml --env-file .env.production --profile migrate run --rm migrate
docker compose -f docker-compose.prod.yml --env-file .env.production up -d
docker compose -f docker-compose.prod.yml --env-file .env.production ps
docker compose -f docker-compose.prod.yml --env-file .env.production logs --tail 100 worker media-encoder
```

Миграции `0008`–`0011` добавляют резервную схему YouTube, кино, языки,
медиакорпус, векторы, цитаты и личные списки. Полный бэкап PostgreSQL включает
`cinema_*`, `media_*` и заметки с цитатами. SQLite-снимок и данные отдельного
Second Brain копируйте отдельно. Кэш модели можно сохранить либо скачать
повторно. Не удаляйте Docker-тома при обычном обновлении.

Экспорт заметок JSON/Markdown пока не экспортирует библиотеку кино и исходный
YouTube-архив. Наличие цитаты в экспорте заметок не заменяет полный бэкап
источников. Основные процедуры — в [OPERATIONS.md](OPERATIONS.md).
